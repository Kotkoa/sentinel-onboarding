# /worklog — ручная запись в WORKLOG.md

Цель: фиксировать в `WORKLOG.md` решения, заметки об использовании AI и проверки качества
**по ходу работы**, чтобы в конце собрать `APPROACH.md` без реконструкции постфактум.

Автоматический `UserPromptSubmit` hook уже пишет сырые промпты в секцию **Process**.
Этот скилл добавляет осмысленные ручные записи в одну из трёх секций.

## Что делать

1. Определи целевую секцию по сути записи:
   - **Decisions** — архитектурное/продуктовое решение + обоснование (по умолчанию).
   - **AI-usage** — что промптил AI, что принял как есть, что переписал и почему.
   - **Quality** — как проверял корректность (тест, code-review, a11y-аудит, сверка с CSV).
2. Сформулируй запись одной-тремя строками: коротко, по делу, с «почему».
3. Допиши её в конец нужной секции `WORKLOG.md` через Edit (не перезаписывай файл целиком).
   Формат строки: `- [<тег>] <текст>` где тег — короткий контекст (`step-4`, `rules`, `a11y` и т.п.).
4. Подтверди пользователю одной строкой, в какую секцию записал.

## Аргументы

- `/worklog <текст>` — записать `<текст>` (секцию определи сам по смыслу).
- `/worklog quality: <текст>`, `/worklog ai: <текст>`, `/worklog decision: <текст>` —
  явно указать секцию (`Quality` / `AI-usage` / `Decisions`).
- `/worklog` без текста — спроси у пользователя, что записать, или предложи саммари
  последнего сделанного шага для подтверждения.

## Правила

- Записи на русском (как и весь чат); код/идентификаторы в записях — на английском.
- Не дублируй то, что уже есть в Process-логе промптов — фиксируй вывод/решение, а не сам промпт.
- Никогда не трогай git и не перезаписывай WORKLOG целиком — только добавление через Edit.
